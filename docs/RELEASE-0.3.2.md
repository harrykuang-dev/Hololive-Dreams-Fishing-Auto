# v0.3.2：角色配色與不同電腦的拉扯節奏

## 定位與修復

- 按角色變化的繼續／下一步及 X 色相：以多個獨立色相遮罩搜尋，再確認白框、字形或圓圈 X 結構。不把所有色相合併成一張遮罩，以免背景裝飾連到按鈕輪廓。測試涵蓋八組色相，不代表逐個角色實機驗證。
- 拍屏視頻魚標飽和度低於舊門檻：保留原本高飽和識別為優先，漏掉時才在已确认金色軌道內尋找低飽和、比內槽寬的魚形橫列，避免把淺藍槽當魚。
- 黃色滑塊高光區的飽和度低，可能只剩局部被識別：適度降低滑塊局部门檻，仍限制在金色軌道的左槽，不修改 TAP 規則。
- 舊控制器把滑塊預測到 200ms、魚預測到最多 80ms。兩者同速移動時仍產生位置偏差。改成同一時間點比較相對位置與速度，快魚使用較短預測時域，並補償本輪可測的擷取／辨識延遲。
- 舊版每次辨識才決定一次按下／放開，低幀率或診斷 PNG 寫入會拉長脈衝。改為獨立的 20Hz 脈衝時鐘；圖像線程只更新長按、放開或脈衝占空比。跟踪消失、退出拉扯、停止、切換前景時放開；超過 150ms 沒有新指令也放開。此機制不能消除遊戲自身的渲染／輸入延遲或嚴重系統卡頓。

## 驗證與限制

88 項單元測試通過，涵蓋同速不偏移、處理延遲補償、低飽和魚與滑塊、多色按鈕、脈衝不依賴新影格、看門狗放開、導覽期間不干擾點擊、工作線程錯誤傳回。

568 張既有場景采樣圖比較 v0.3.0：沒有新增／遺失導覽操作，也沒有 TAP 判斷變化。使用者拍屏影片在 30Hz 離線采樣中，修復前 35 幀同時找到魚與滑塊，最終修復 55 幀；拍屏的曝光、透視與手持移動仍會影響識別，這不是遊戲直接擷取的成功率。

`python tools/simulate_reel.py` 提供可重跑的簡化慣性滑塊模型，測試 10／15／20／40Hz、0／40／80ms 延遲和兩種判定格大小，共 24 組。模型參數並非遊戲實測物理值；結果只能用於算法壓力比較，不能當作實機勝率。仍需對方電腦以新版 EXE 驗證。

請勾選「儲存本機診斷」。`trace.csv` 新增 `capture_ms`、`vision_ms`、`sample_ms`、`age_ms`，分別記錄擷取耗時、辨識耗時、取樣間距、指令決策前的影格年齡估計。與魚／滑塊位置、追蹤狀態一起提供，可區分識別中斷、效能瓶頸與控制偏差。無法從拍屏录像单独证明對方具體幀率或輸入是否送達。
