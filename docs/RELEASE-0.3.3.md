# v0.3.3：撤回拉扯退化並恢復失效長按

## 最新實測證據

診斷來源為本機 `20260930-124737`，與使用者提供的 12:49:19 桌面录像時間相符，录像覆盖诊断后半段。診斷包含七段拉扯，共 1,398 個有效跟蹤影格，全部有魚和滑塊資料，沒有短暫預測影格。各段取樣間隔中位數約 32.6–32.8ms，擷取約 19ms、辨識約 3.3ms，影格年齡估計約 13ms。不是嚴重低幀率或持續識別丟失。

第一段和末段長時間記錄 `control=hold,held=1`，但滑塊持續停在底部，與录像後段滑塊沒有跟隨上行魚標的現象吻合。`held` 是程式自己的狀態，不等於遊戲已接受鼠標按下；0.3.2 沒有記錄作業系統鍵態，因此不能僅憑現有資料斷言是哪一次 Windows／遊戲輸入事件丟失。已確認新版控制／輸入變更沒有達到預期，不能再依簡化模型宣稱更穩。

## 修復

- 撤回異步 20Hz 脈衝工作線程，所有拉扯輸入重新由單一控制線程按有效影格按下／放開。
- 恢復 v0.3.0 的預測煞車與近魚脈衝決策，不沿用 0.3.2 的同時域／快速魚調參。角色配色、低飽和識別和耗時診斷保留。
- 長按期間需要繼續向上追魚，卻 300ms 沒有至少 1.5% 畫面高度的上浮進展時，松開一個控制影格，下一幀重新按下。正常上浮、魚已在滑塊附近、預測／丟失跟蹤不觸發此重按。
- `MouseController.press` 不再只信 `held`；若 Windows 左鍵已被外部松開，會重新發出按下。
- `trace.csv` 新增 `os_down`（Windows 左鍵實際鍵態，不等於遊戲接收證明）、`rearm`（無上浮進展的重按觸發）欄位。識別過舊或跟蹤丟失仍放開。
